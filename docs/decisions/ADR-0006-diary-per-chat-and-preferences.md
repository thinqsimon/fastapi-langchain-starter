# ADR-0006 채팅 단위 배움일기와 개인 설정

- 상태: 채택 (2026-10-20)
- 관련 기능: PREF-01, ACC-01, UX-01, UX-02, DIARY-01~03 (`harness/feature_list.json` phase 5)

## 맥락
샘플앱을 써 본 뒤 다음 요구가 나왔다.

- 일기 단위를 **날짜에서 채팅으로** 바꾼다. 채팅을 골라 그 대화로 일기를 쓴다.
- 같은 날 여러 편을 쓸 수 있어야 한다. 제목은 `2026-10-20(2) 핵심단어`처럼 순번을 붙인다.
- 같은 채팅은 **마지막 일기 이후 대화가 추가됐을 때만** 다시 고를 수 있고, 새 일기는 추가된 대화만 다룬다.
- '배운 내용 상세' 항목을 추가한다. 주제별 소제목으로 길이 제한 없이, 복습에 필요한 설명을 보충해 쓴다.
- '내일 할 것'은 대화에 없으면 만들지 않고, 비어 있으면 항목 없이 저장한다.
- 개인별 캐치프레이즈(헤더 가운데, 넘치면 전광판)와 일기 푸터(저장 시 맨 끝에 추가)를 설정한다.
- 우측 상단 계정 메뉴를 사이드 메뉴로 바꾸고, 설정에서 이름·이메일·비밀번호를 고친다.

## 결정

### 일기 (diary 도메인)
| 항목 | 선택 | 이유 |
|---|---|---|
| 같은 날 여러 편 | 유니크를 `(user_id, entry_date)` → `(user_id, entry_date, day_sequence)`로 변경 | 하루 한 편 제약을 없애면서 순번이 겹치지 않게 DB가 보장한다 |
| 순번 | 그날 최댓값 + 1 | 지운 번호를 다시 쓰지 않아 제목 `(n)`이 다른 일기와 헷갈리지 않는다 |
| 제목의 `(n)` | 초안에서 붙이고, **저장할 때 실제 순번으로 다시 맞춘다** | 초안을 만든 뒤 다른 일기가 먼저 저장될 수 있다. 날짜로 시작하지 않는 제목은 사용자가 고친 것으로 보고 건드리지 않는다 |
| 오늘 날짜 | 화면이 사용자 기기 기준 날짜를 보낸다(없으면 UTC) | 서버는 UTC라 한국 00~09시에는 하루 전 날짜가 된다 |
| 재발행 조건 | 일기마다 `source_last_message_at`(다룬 마지막 메시지 시각)을 저장하고, 채팅의 마지막 메시지가 그보다 뒤일 때만 고를 수 있다 | 별도 상태 없이 메시지 시각만으로 판단한다. 일기를 지우면 자연히 다시 고를 수 있다 |
| 재발행 범위 | 그 시각 이후 메시지만 일기 대상, 이전 메시지는 프롬프트에 "맥락"으로만 넣는다 | 같은 내용을 두 번 쓰지 않으면서 대화 흐름은 이해하게 한다 |
| API 직접 호출 | 초안·저장 모두 서버에서 다시 검사해 409 | 목록에서 숨기는 것만으로는 막을 수 없다. 미래 시각을 보내도 실제 마지막 메시지로 맞춘다 |
| '내일 할 것' 근거 확인 | 모델에게 근거 문장을 대화에서 그대로 인용하게 하고, 그 문장이 새 대화에 없으면 비운다 | "없으면 비워 두라"는 지시만으로는 모델이 그럴듯한 계획을 지어낸다. 결정적으로 테스트할 수 있다 |
| 빈 '내일 할 것' | `NULL`로 저장하고 화면에서 항목을 숨긴다 | "비어 있으면 항목 자체를 뺀다"는 요구 그대로 |
| 푸터 | 저장 시점의 문구를 일기 행에 복사(`footer`) | 설정을 나중에 바꿔도 지난 일기는 그대로여야 한다. 읽을 때 합치면 지난 일기까지 바뀐다 |
| 상세 렌더링 | `react-markdown` + `remark-gfm` | 원본 HTML을 그리지 않아 LLM 출력에 스크립트가 섞여도 안전하다 |

### 개인 설정 (preferences 도메인)
| 항목 | 선택 | 이유 |
|---|---|---|
| 저장 위치 | 서버 `user_preferences` 테이블(사용자당 1행, PK = user_id) | 다른 기기에서도 같은 값이 보여야 한다 |
| 기본값 | 코드에 두고, 행이 없으면 기본값을 돌려준다 | 기본 문구를 바꾸면 한 번도 설정하지 않은 사람에게 바로 반영된다 |
| 기본값으로 되돌리기 | `DELETE /api/me/preferences`(행 삭제) | 위와 같은 이유로 기본값을 복사해 저장하지 않는다 |
| 빈 값 | 허용 | 비운 캐치프레이즈는 보이지 않고, 비운 푸터는 일기에 붙지 않는다 |

### 계정 정보 수정 (auth 도메인 확장)
| 항목 | 선택 | 이유 |
|---|---|---|
| 현재 비밀번호가 틀림 | **400** `WRONG_PASSWORD` | 401을 주면 프론트엔드 인터셉터가 토큰 재발급을 시도하다 결국 로그아웃시킨다 |
| 이메일 변경 | 현재 비밀번호 확인, 중복이면 409 | 로그인 ID가 바뀌는 일이라 본인 확인을 한 번 더 한다 |
| 비밀번호 변경 | 모든 리프레시 토큰을 폐기하고 새 토큰 쌍을 돌려준다 | 다른 기기는 끊고 지금 화면은 유지한다 |

### 화면
- 계정 메뉴는 shadcn `sheet`(Base UI Dialog)를 오른쪽에서 연다. 계정 정보·사용량·설정·로그아웃을 담는다.
  헤더 가운데 공간을 캐치프레이즈에 주려고 사용량 표시도 메뉴 안으로 옮겼다.
- 전광판은 React 상태 없이 `ResizeObserver` + Web Animations API로 만든다.
  넘칠 때만 `오른쪽 바깥 → 왼쪽 바깥` 이동 뒤 10초 정지 구간을 한 애니메이션에 넣고 무한 반복한다.
  `prefers-reduced-motion`이면 흐르지 않고 말줄임표로 자른다. 현재 상태를 `data-motion`으로 드러내 E2E가 확인한다.

## 결과
- 마이그레이션 `c85195cc050f`: `user_preferences` 생성, 일기 컬럼 추가, 유니크 교체.
  기존 일기의 제목은 날짜로 채운다. 왕복(upgrade → downgrade → upgrade)과 `alembic check` 확인
- 백엔드 테스트 161개(커버리지 97%), E2E 22개. 인수조건마다 테스트 이름에 그 조건을 드러냈다

## 한계
- 비밀번호를 바꿔도 다른 기기의 **액세스 토큰**은 만료(기본 30분)까지 유효하다. JWT를 상태 없이 쓰기 때문이다.
  리프레시가 막히므로 그 뒤에는 다시 로그인해야 한다
- 모델이 근거 문장을 조금 바꿔 인용하면 실제로 있던 '내일 할 것'도 비워진다. 지어내는 것보다 안전한 쪽을 택했고, 사용자가 직접 채울 수 있다
- 같은 날 거의 동시에 두 번 저장하면 한쪽은 409(다시 시도 안내)를 받는다
- 다운그레이드 시 같은 날 일기가 여러 편이면 예전 유니크(하루 한 편)를 다시 만들 수 없다. 마이그레이션 주석에 적어 두었다

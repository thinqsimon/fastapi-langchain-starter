# ADR-0005 RAG 모듈 (선택 기능)

- 상태: 채택 (2026-10-15)

## 맥락
문서를 근거로 답하는 기능은 챗봇 서비스에서 자주 요구된다. 다만 **모든 서비스가 필요한 것은 아니라서**
코어에 넣으면 쓰지 않는 사람에게 부담이 된다.

## 결정
| 항목 | 선택 | 이유 |
|---|---|---|
| 저장소 | PostgreSQL + pgvector | 별도 벡터 DB를 띄우지 않아도 된다. 운영 부담이 적다 |
| 연동 방식 | SQLAlchemy로 직접 구현 | `langchain-postgres`는 의존성 충돌이 있었고, 직접 구현이 더 짧고 읽기 쉽다 |
| 켜고 끄기 | `RAG_ENABLED` | 꺼지면 라우터가 등록되지 않아 `/docs`에도 보이지 않는다 |
| 분할 | 직접 구현(`llm/rag/splitter.py`) | 문단→줄→문장→공백 순서로 자연스러운 경계를 찾는다. 의존성을 늘리지 않았다 |
| 테스트 임베딩 | 해시 기반 결정적 임베딩 | 무작위 벡터를 쓰면 검색 순서가 의미 없어져 "검색이 되는지"를 검증할 수 없다 |
| 재색인 | 같은 이름이면 기존 조각 삭제 후 저장 | 옛 내용이 계속 검색되는 문제를 막는다 |

## 결과
- 문서 저장·목록·삭제·검색 API 4개, 테스트 13개
- 실제 OpenAI 임베딩으로 "노트북은 언제 바꿔주나요?" → 장비 관련 조각을 1위로 검색 확인
- 벡터 확장은 마이그레이션이 `CREATE EXTENSION IF NOT EXISTS vector`로 준비한다

## 한계
- 검색 결과를 답변 생성에 자동으로 넣지는 않는다. 서비스마다 프롬프트 설계가 달라서,
  `chains/`에서 조합하도록 남겨 두었다
- 인덱스(IVFFlat/HNSW)를 걸지 않았다. 조각 수가 많아지면 추가해야 한다

# ADR-0009: 저장되는 주간 회고와 일기 기반 복습

- 날짜: 2026-10-26
- 상태: 채택
- 기능: COACH-02

## 범위

사용자의 주간 회고 저장·복습 구현 요청에 따라 기존 diary 도메인에 저장 구조와 API를
추가한다. 기존 API 계약과 마이그레이션은 유지하고, 서비스 브랜치에서 신규 마이그레이션을
검증한다. 운영 DB에 직접 적용하거나 배포하지 않는다. DOC-02보다 사용자 요청을 우선한다.

## 저장 정책

회고는 사용자가 선택한 날짜가 속한 월요일~일요일의 일기로 생성하고 바로 저장한다.
UI에서 자동 저장됨을 알린다. 사용자·주 시작일의 유일 제약으로 한 주에 한 편만 보관한다.
반복 요청은 기존 회고를 반환해 추가 LLM 호출과 중복 저장을 막는다. 원본 일기를 나중에
수정·삭제해도 저장 당시 회고는 보존한다. 재생성하려면 확인 창에서 기존 회고를 삭제한다.
기존 GET /api/diary/weekly 미저장 생성 API는 호환성을 위해 유지한다.

복습은 실제 일기의 어려웠던 내용으로 구성하며 문제·정답을 새로 지어내지 않는다.
학습 내용 펼쳐 보기, 내 말로 정리하는 메모, 완료/다시 복습을 제공한다. '없음' 등 명시적인
빈 어려움은 제외한다. 일기 하나에 진행 상태 하나를 두고 FK/PK로 중복을 막는다.
메모와 완료 상태는 함께 저장하며 원문의 어려움이 바뀌면 완료만 해제하고 메모는 보존한다.
일기 삭제 시 진행 상태는 CASCADE로 삭제된다.

## API와 데이터

- `GET /api/diary/reviews`: 본인 회고 목록
- `POST /api/diary/reviews {reference}`: 선택 주 회고 생성·저장 또는 기존 회고 반환
- `DELETE /api/diary/reviews/{id}`: 본인 회고 삭제
- `GET /api/diary/study`: 본인 일기의 복습 항목과 진행 상태
- `PUT /api/diary/study/{entry_id} {completed,note}`: 메모·상태 저장

`diary_weekly_reviews`의 (user_id,week_start) 유일 인덱스는 사용자별 조회에도 사용한다.
`diary_study_progress.entry_id` PK는 FK 조회와 삭제를 지원한다. 복습 조회는 소유자 일기와
진행 상태를 한 번에 JOIN해 N+1을 피한다. 모든 읽기·쓰기는 인증 사용자로 제한하며 타인 ID는
404다. 별도의 의존성이나 새 도메인은 추가하지 않는다.

프론트엔드는 API 모듈과 Zustand learning 스토어를 사용한다. 계정 세대와 요청 버전을
구분해 로그아웃·늦은 조회가 새 상태를 덮지 않게 한다. 저장 중에는 해당 입력을 잠그고
실패 시 메모를 보존한다. starter에는 API·화면·요청이 노출되지 않는다.

# ADR-0017: 관리자 비밀번호 초기화와 사용자 삭제 (ADMIN-05)

- 상태: 채택 (2026-10-31)
- 관련: ADR-0013(관리자가 사용자 계정으로 테스트), ADR-0015(요금제 쿠폰), `backend/src/app/domain/admin/`, `frontend/components/admin/`

## 배경

교육생이 비밀번호를 잊으면 메일 같은 재설정 수단이 없어 관리자가 직접 풀어 줘야 한다.
운영 DB에는 배포 확인용·테스트 계정이 쌓이는데 지울 화면이 없었다.

## 결정

### 비밀번호 초기화
- `POST /api/admin/users/{id}/password-reset` `{password?}`. 비우면 서버 설정 `ADMIN_RESET_PASSWORD_DEFAULT`(비우면 `12345678`),
  넣으면 그 값으로 바꾼다. 길이는 가입 규칙과 같은 8~72자다.
- 초기화하면 그 계정의 리프레시 토큰을 모두 폐기한다(비밀번호 변경과 같은 규칙). 이미 발급된 액세스 토큰은 수명까지 남는다.
- 다음 로그인 때 변경을 강제하지 않는다(사용자 결정, DB 변경 없음). 대신 관리자 화면의 안내문에 "로그인한 뒤 설정에서 바꿔 주세요"를 넣는다.
- 응답에는 비밀번호를 싣지 않고 `password_source`(`default`/`custom`)만 준다. 기본 암호 값은 관리자가 사용자에게 알려 줘야 하므로
  `GET /api/admin/password-reset/default`로 관리자 화면에 보여 준다.
- 기본 암호 설정이 규칙에 맞지 않아도 서버는 뜬다. 부팅 실패는 운영 전체를 멈추므로, 초기화 시점에 503으로 알리고 직접 입력 초기화는 계속 허용한다.
- 로그에는 관리자 id, 대상 id, 출처, 끊은 세션 수만 남긴다. 비밀번호와 이메일은 남기지 않는다.

### 사용자 삭제
- `DELETE /api/admin/users/{id}`는 비활성화가 아니라 완전 삭제다. users를 참조하는 테이블은 DB의 `ON DELETE CASCADE`로 함께 지워지고,
  쿠폰은 `SET NULL`이라 발급·사용 기록이 남는다.
- ORM의 `session.delete()` 대신 `DELETE` 문을 바로 보낸다. ORM은 자식 행의 외래 키를 먼저 비우려다 NOT NULL 제약에 막힐 수 있기 때문이다.
- 화면은 확인 대화상자에서 지워지는 범위(기록 전부, 쿠폰은 기록만 남음, 같은 이메일로 재가입 가능)를 먼저 보여 준다.

### 공통
- 관리자 계정(설정 파일 `ADMIN_EMAILS`, 자기 자신 포함)은 초기화·삭제 대상이 아니다(403). 관리자 권한을 가진 쪽끼리 계정을 빼앗거나
  지우는 일을 막는다. 검색 결과에 `is_admin`을 실어 화면에서 버튼을 끈다.
- "이 계정으로 테스트" 중에는 토큰 주인이 대상 사용자라 관리자 API 자체를 쓸 수 없다.

## 대안과 기각 이유
- **임시 비밀번호 자동 생성**: 더 안전하지만 요청(정해진 기본 암호 또는 입력한 암호)과 다르다. 직접 입력으로 계정마다 다른 값을 줄 수 있다.
- **다음 로그인 때 변경 강제**: users에 컬럼을 더하고 로그인 뒤 변경 화면으로 보내야 한다. 사용자가 원하지 않았다. 필요해지면 `must_change_password`로 확장한다.
- **비활성화(소프트 삭제)**: 복구는 쉽지만 개인 기록이 남고 같은 이메일로 다시 가입할 수 없다. 테스트 계정 정리라는 목적에 맞지 않는다.

## 결과
- 기본 암호를 아는 사람은 사용자가 바꾸기 전까지 초기화된 계정에 로그인할 수 있다. 안내문으로 변경을 권하고, 걱정되면 직접 입력을 쓴다.
- 삭제는 되돌릴 수 없다. 필요하면 운영 DB 백업으로만 복구할 수 있다.

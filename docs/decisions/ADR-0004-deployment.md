# ADR-0004 배포 구성

- 상태: 채택 (2026-10-15)

## 맥락
무료 플랜으로 배포해야 하고, 제출(11/03) 이후에도 산출물 링크가 살아 있어야 한다.
처음에는 Render 하나로 통일하려 했으나 무료 플랜 조건을 확인하니 문제가 있었다.

| 항목 | Render 무료 | 영향 |
|---|---|---|
| PostgreSQL | **생성 30일 후 만료**, 이후 접근 불가 | 10/15 생성 시 11/14 만료. 제출 후 확인하면 서비스가 죽어 있다 |
| 웹 서비스 | 15분 미사용 시 중지, 복귀에 약 1분 | 발표 시연에서 첫 요청이 느리다 |
| 인스턴스 시간 | 워크스페이스당 월 750시간 | 백엔드·프론트를 모두 Render에 두면 빠듯하다 |

## 결정
| 역할 | 선택 | 이유 |
|---|---|---|
| DB | **Supabase** | 만료 기한이 없다. 7일 미사용 시 일시정지되지만 데이터는 보존되고 대시보드에서 복구된다. pgvector 기본 지원. 수업(`2026_FullStack_BE`)에서 이미 사용해 익숙하다 |
| 백엔드 | **Render** | FastAPI 배포가 단순하고 Deploy Hook으로 CI와 연결하기 쉽다 |
| 프론트엔드 | **Vercel** | Next.js에 최적화돼 있고 중지되지 않는다 |

Render 웹 서비스를 하나만 쓰게 되어 750시간 제약에서도 여유가 생긴다.

## 결과
- 스타터킷은 특정 배포처에 묶이지 않는다. `DATABASE_URL`과 환경 변수만 바꾸면 다른 곳에도 올릴 수 있다
- 백엔드는 무료 플랜 특성상 15분 뒤 중지된다. **시연 전에 미리 한 번 호출해 깨워 둔다**
- Supabase는 연결 풀러(포트 6543) 주소를 쓴다. 서버리스·저사양 환경에서 연결 수를 아낄 수 있다

## 대안
- **전부 Render**: 구성은 단순하지만 11/14경 DB가 만료된다. 제출 후 재생성하거나 유료 전환이 필요하다
- **전부 유료**: 월 $7부터. 과제 범위에서는 과하다

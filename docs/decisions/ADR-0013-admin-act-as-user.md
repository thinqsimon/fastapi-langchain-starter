# ADR-0013: 관리자가 사용자 계정으로 테스트하기 (ADMIN-02)

- 상태: 채택 (2026-10-30)
- 관련: ADR-0003(사용자 스키마), ADR-0012(관리자 서버 설정), `backend/src/app/domain/auth/dependencies.py`, `backend/src/app/domain/admin/`

## 배경

사용자가 "일기가 안 만들어진다", "학습장이 안 올라간다"고 신고하면, 관리자가 **그 계정 그대로** 같은 화면을 열어
재현해야 원인을 찾을 수 있다. 비밀번호를 받을 수는 없고, 관리자용 조회 API를 화면마다 따로 만드는 것은 중복이 크다.

## 결정

### "대신 쓰는 토큰"으로 기존 화면·API를 그대로 쓴다
- `POST /api/admin/users/{id}/acting-token`이 **대상 사용자 명의의 액세스 토큰**을 돌려준다. 토큰에는 `act`(행위자 = 관리자 id)가 들어간다.
  리프레시 토큰은 주지 않는다. 수명은 `ADMIN_TEST_TOKEN_EXPIRE_MINUTES`(기본 60분).
- 프론트는 관리자 토큰을 그대로 둔 채 테스트 토큰을 별도 키(`acting_access_token`)에 저장하고, 있으면 모든 요청에 그 토큰을 쓴다.
  그래서 채팅·학습장·일기·설정 **어느 API도 바꾸지 않고** 그 사용자의 화면이 그대로 보인다.
- 돌아가기를 누르거나 토큰이 만료(401)되면 테스트 토큰을 버리고 관리자 토큰으로 복귀한다. 만료 때는 토큰을 재발급하지 않는다
  (재발급하면 조용히 관리자 화면으로 바뀌어 "지금 누구 계정인지"가 흐려진다).

### 쓰기는 허용, 되돌리기 어려운 것만 차단
- 오류 재현에는 메시지 보내기, 일기 생성·저장, 학습장 업로드가 필요하므로 **쓰기를 허용**한다. 만든 데이터는 그 사용자 계정에 남는다.
- `act`가 있는 토큰으로 오는 요청 중 **모든 `DELETE`**와 **`/api/auth/*`의 쓰기**(이름·이메일·비밀번호 변경)는
  `get_current_user`에서 403 `테스트 중에는 삭제·계정 변경을 할 수 없습니다.`로 막는다. 한 곳에서 막으므로 도메인이 늘어도 규칙이 새지 않는다.
- 대상이 관리자 자신이면 400, 없거나 비활성이면 404.

### 감사 기록은 서버 로그로만
- 시작: `admin_test_started admin=<id> target=<id> minutes=<n>`
- 테스트 중 모든 쓰기 요청: `admin_test_write admin=<id> target=<id> method=<M> path=<p>` (본문은 남기지 않는다)
- DB 테이블은 두지 않는다. 지금은 관리자 한 명이고, 필요하면 Render 로그에서 `admin_test_`로 찾는다. 화면 조회가 필요해지면 그때 테이블을 만든다.

### 화면
- `/admin`(이름을 "서버 설정"에서 **관리자**로 바꿈)에 **"사용자 계정으로 테스트"** 카드: 이메일·이름 검색 → `이 계정으로 테스트`.
- 테스트 중에는 헤더 아래에 노란 띠: 누구 계정인지, 만든 내용은 그 계정에 남는다는 안내, `내 계정으로 돌아가기`.
  계정 메뉴에는 대상 사용자의 정보가 보인다(정말 그 사람 화면임을 확인).
- 새 라우트는 없다(Vercel Hobby 함수 수 이슈와 무관하게 유지).

## API
- `GET /api/admin/users?q=&limit=` → `[{id, email, display_name, is_active, created_at}]` (이메일·이름 부분 일치, 최근 가입순)
- `POST /api/admin/users/{id}/acting-token` → `{access_token, token_type, expires_in, user}`

## 대안과 기각 이유
- **읽기 전용 보기**: 오류 재현이 안 된다. 사용자가 보는 그대로 동작시켜야 원인이 보인다.
- **관리자용 조회 API를 도메인마다 추가**: 화면·API 중복이 크고 새 기능마다 또 만들어야 한다.
- **사용자 비밀번호 임시 변경**: 사용자를 잠그고 흔적이 남지 않는다.

## 주의
- 테스트 중 만든 대화·일기는 사용자에게 그대로 보인다. 끝난 뒤 관리자 계정으로 돌아가면 삭제가 막혀 있으니, 정리가 필요하면
  사용자에게 알리거나 추후 "테스트 흔적 정리" 기능(`act` 로그 기반)을 추가한다.

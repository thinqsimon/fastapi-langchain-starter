## 1. 필수 구현 (13)

### ✅ 1-1. 스타터킷 포함 범위 및 디렉터리 구조 설계 — 완성도 100%

재사용 기준을 "두 개 이상 서비스에서 수정 없이 쓰이면 코어"로 정의하고, 모듈별로 유지/변경 지점을 표로 명시.

- 근거: [docs/plans/01_선정_및_범위.md](../plans/01_선정_및_범위.md) 포함/제외 표, [02_스타터킷_설계서.md](../plans/02_스타터킷_설계서.md) ③ 모듈 표(11개 모듈)

### ✅ 1-2. FastAPI 계층형 백엔드 — 완성도 100%

`domain/<기능>/`에 routers · services · repositories · models · schemas 분리.
**문서가 아니라 도구가 강제**합니다.

- 근거: `backend/src/app/domain/auth/` 5개 계층 파일 확인
- 근거: `uv run lint-imports` → `Contracts: 3 kept, 0 broken`
- 검증: 계층을 어긴 import를 넣으면 테스트가 실패함을 실제로 확인

### ✅ 1-3. PostgreSQL 스키마 · SQLAlchemy · Alembic — 완성도 100%

테이블 5개(users, refresh_tokens, conversations, messages, diary_entries), 마이그레이션 3개.

- 근거: `backend/alembic/versions/` 3개 파일
- 근거: 운영 DB(Supabase)에 `alembic upgrade head` 적용 완료
- 검증: upgrade → downgrade → upgrade 왕복 성공, `alembic check` 깨끗
- 추가 안전장치: 모델을 만들고 등록하지 않으면 실패하는 테스트

### ✅ 1-4. JWT 인증 (회원가입·로그인·리프레시) — 완성도 100%

5개 엔드포인트. 리프레시 토큰은 **회전**시켜 한 번 쓴 토큰을 폐기합니다.

- 근거: `/api/auth/{signup,login,refresh,logout,me}`
- 검증: 운영 환경에서 가입 201 → 로그인 → `/me` 200 확인
- 보안 결정: 로그인 실패 메시지를 구분하지 않아 가입 여부가 드러나지 않음

### ✅ 1-5. 공통 예외 처리 및 로깅 — 완성도 100%

모든 에러 응답이 `{"error":{"code","message"}}` 한 형식. 요청마다 `X-Request-ID`로 추적.

- 근거: `core/exceptions.py` 핸들러 4개, `core/logging.py`, `core/middleware.py`
- 검증: 500 응답에 내부 메시지가 섞이지 않는지 회귀 테스트로 단정

### ✅ 1-6. React 프론트엔드 기본 구조 — 완성도 100%

Next.js(App Router). 인증 화면, 보호 라우트, 공통 컴포넌트, API 클라이언트.

- 근거: `frontend/app/(auth)`, `app/(main)`, `api/` 7개 모듈, `store/` 3개, `components/ui` shadcn
- 특기: 401 시 토큰 자동 재발급(동시 요청은 1회만 호출)

### ✅ 1-7. LangChain LLM 연동 모듈 — 완성도 100%

프롬프트 템플릿 분리, `.env`만으로 공급자 교체, SSE 스트리밍, 구조화 출력.

- 근거: `llm/providers.py`, `llm/prompts/`, `llm/chains/`, `llm/fake.py`
- 검증: 실제 OpenAI로 스트리밍 응답과 일기 초안 생성 확인

### ✅ 1-8. 환경 변수 분리 및 `.env.example` — 완성도 100%

- 근거: `.env.example`, `core/config.py` 단일 진입점
- 안전장치: 설정과 예시 파일이 어긋나면 실패하는 테스트 3개
- 운영 보호: `APP_ENV=production`에서 약한 비밀키·키 누락 시 기동 차단

### ✅ 1-9. GitHub Actions CI/CD — 완성도 100%

- 근거: CI #19 성공(검사 95초 + 브라우저 E2E 84초), Deploy 성공
- 검증: `git push` → CI → 배포 게이트 → Render 배포 → `/health` 확인까지 자동 수행
- 설계: 배포 대상 미설정 시 배포 단계를 **건너뜀**(배포 안 했는데 초록불 방지)

### ✅ 1-10. 테스트 코드 — 완성도 100%

- 근거: 백엔드 90개 + 브라우저 E2E 12개, 커버리지 96%
- 게이트: 90% 미만이면 CI 차단
- 특기: 테스트가 실제 LLM을 부르지 않는지, 운영 DB에 붙지 않는지도 테스트로 강제

### ✅ 1-11. 샘플 서비스 1개 — 완성도 100%

AI 배움일기 코치. 코칭 대화 → 일기 초안 생성 → 저장 → 주간 회고.

- 근거: `backend/src/app/domain/diary/`, `frontend/app/(main)/diary/`, [samples/diary-coach/](../../samples/diary-coach/)
- 검증: 운영 환경에서 실제 LLM으로 초안 생성 확인
- 가치: **새로 만든 것이 프롬프트·도메인 1개·화면 1개뿐**임을 보여 재사용성을 증명

### ✅ 1-12. Fork 후 실행·커스터마이징·배포 문서화 — 완성도 100%

- 근거: [README.md](../../README.md), [사용 및 운영 가이드](../guides/usage.md) 353줄(①~⑨ 전 항목)
- 특기: 모든 명령을 실제 실행해 기대 출력까지 기록

### 🟡 1-13. 신규 환경에서 문서만으로 실행·배포 검증 — 완성도 70%

- ✅ 자동 검증 통과: `make fork-verify`(임시 폴더 clone → init → verify)
- ✅ 이 검증으로 **Fork 직후 100% 실패하던 버그 2건**을 발견·수정
- ✅ 운영 환경 배포까지 성공
- ❌ **남은 것: 다른 사람이 README만 보고 실행해 보기** (팀원 요청 필요)
- 근거: [fork-verification.md](../guides/fork-verification.md)

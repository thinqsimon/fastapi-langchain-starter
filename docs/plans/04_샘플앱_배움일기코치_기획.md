# 04. 샘플앱 기획 — AI 배움일기 코치

> 2026-10-20 v2: 일기 단위를 채팅으로 바꾸고 항목·설정을 늘렸다. 아래 [v2 변경](#v2-변경-2026-10-20)이 현재 기준이다.

## 한 줄 소개
교육생이 오늘 배운 내용을 AI와 대화로 풀어내면, AI가 질문으로 정리를 돕고 **배움일기 초안**을 만들어 저장한다. 주 단위로 **회고 요약**을 제공한다.

## 왜 이 앱인가
- 과정의 실제 일과(매일 17시 배움일기)와 연결돼 시연 공감도가 높다
- 스타터킷의 코어(인증·대화·스트리밍)를 그대로 쓰고, **프롬프트·도메인 모델·화면만** 바꾸면 되는 구조라 재사용성 증명에 적합하다

## 사용자 시나리오
1. 로그인 → "오늘의 코칭" 시작
2. 코치: "오늘 가장 기억에 남는 개념은?" → 사용자 답변 → 코치가 꼬리 질문 (스트리밍)
3. "일기로 정리" 버튼 → 대화 기반 일기 초안(배운 것 / 어려웠던 것 / 내일 할 것) 생성
4. 사용자가 수정 후 저장
5. 일기 목록에서 지난 기록 확인, "이번 주 회고" 요약 생성
6. (선택, RAG) "예전에 배운 것 찾기" — 지난 일기에서 검색

## 프롬프트 초안
- 코치(system): "너는 IT 부트캠프 교육생의 학습 코치다. 정답을 알려주기보다 질문으로 스스로 정리하게 돕는다. 한 번에 질문은 하나, 3~4문장 이내."
- 일기 초안: 대화 전체를 입력으로 `learned / difficult / next_plan` 필드를 가진 구조화 출력(`with_structured_output`)
- 주간 회고: 해당 주 일기들을 입력으로 "성장한 점 / 반복된 어려움 / 다음 주 제안"

## 스타터킷 대비 변경 지점 (→ 사용 가이드 "커스터마이징" 예시)
1. `.env`의 APP_NAME 변경
2. `llm/prompts/diary_coach.py` 추가, chat 서비스의 system 프롬프트 설정값 교체
3. `/add-domain-model diary` → 모델·마이그레이션
4. diary 서비스·라우터·테스트
5. 프론트 `app/(main)/diary/*`, `api/diary.ts`

## v2 변경 (2026-10-20)
사용해 보며 나온 요구를 반영했다. 설계 이유는 [ADR-0006](../decisions/ADR-0006-diary-per-chat-and-preferences.md).

| 구분 | v1 | v2 |
|---|---|---|
| 일기 단위 | 날짜(하루 한 편) | 채팅. 같은 날 여러 편, 제목에 `(2)`, `(3)` |
| 초안 대상 | 가장 최근 채팅 | 사용자가 고른 채팅. 이미 쓴 채팅은 새 대화가 있을 때만, 새 대화만 다룸 |
| 항목 | 배운 것 / 어려웠던 것 / 내일 할 것 | 제목(날짜 + 핵심 단어), 배운 것, **배운 내용 상세**, 어려웠던 것, 내일 할 것(대화에 있을 때만) |
| 일기 끝 | 없음 | 저장 시점의 개인 푸터 |
| 헤더 | 사용량·이름·로그아웃 | 가운데 캐치프레이즈(전광판), 우측 계정 사이드 메뉴 |
| 설정 | 없음 | `/settings`: 이름·이메일·비밀번호, 캐치프레이즈·푸터 |

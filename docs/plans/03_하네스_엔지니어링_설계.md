# 03. 하네스 엔지니어링 설계

AI 코딩 에이전트가 **세션이 바뀌어도 맥락을 잃지 않고, 한 번에 한 기능만, 스스로 검증하며** 작업하도록 저장소를 구성한다.
참고: Anthropic "Effective harnesses for long-running agents", Addy Osmani "Agent Harness Engineering".

## 4계층
| 계층 | 구성 요소 | 목적 |
|---|---|---|
| 안내(맥락) | `CLAUDE.md`(목차), `AGENTS.md`, `backend/CLAUDE.md`, `frontend/CLAUDE.md`, `docs/` | 짧은 목차 + 상세는 docs로 위임 |
| 상태 | `harness/feature_list.json`, `harness/progress.md`, `scripts/init.sh` | 세션 간 인수인계, 할 일·완료 기준의 단일 출처 |
| 검증 | `scripts/verify.sh`, import-linter, pytest(fake LLM), CI | 에이전트·사람·CI가 같은 기준으로 판정 |
| 실행 | `.claude/settings.json`(hooks·권한), `.claude/agents/*`, `.claude/skills/*` | 반복 작업 자동화, 역할 분리, 위험 차단 |

## 세션 루프
```
progress.md 읽기 → feature 1개 선택(/new-feature) → 구현(owner 에이전트)
→ verify.sh → test-verifier 판정 → /handoff(기록·passes·커밋)
```

## feature_list.json 스키마
```json
{ "id": "AUTH-01", "phase": 2, "owner": "backend-dev", "title": "...",
  "requirement": "필수4", "acceptance": ["..."], "verify": "./scripts/verify.sh", "passes": false }
```
규칙: 한 세션 1개 · acceptance 전부 확인 + verify 통과 시에만 `passes:true` · 항목 삭제·완화는 사용자 승인.

## 서브에이전트
| 이름 | 권한 | 역할 |
|---|---|---|
| backend-dev | 읽기·쓰기·실행 | 도메인 계층·마이그레이션·API 테스트 |
| frontend-dev | 읽기·쓰기·실행 | 화면·상태·API 연동 |
| llm-engineer | 읽기·쓰기·실행 | LangChain·프롬프트·SSE·RAG·사용량 |
| test-verifier | **읽기·실행만** | acceptance 독립 판정 |
| docs-writer | 읽기·쓰기 | 설계서·가이드·트러블슈팅 |
| reviewer | 읽기 + 워크플로 수정 | diff 리뷰·CI/CD |

## 스킬
| 스킬 | 하는 일 |
|---|---|
| `/new-feature` | 다음 기능 선택·브랜치·acceptance 체크리스트 |
| `/add-domain-model` | 도메인 폴더 스캐폴드 + 등록 3곳 + 마이그레이션 |
| `/handoff` | verify → passes 갱신 → progress 기록 → 커밋 |
| `/fork-verify` | 새 폴더 clone → init → verify, 결과 기록 (4단계 검증 자동화) |

## Hooks
- `PreToolUse(Read|Edit|Write)`: `.env*` 접근 차단 (`.env.example` 제외)
- `PostToolUse(Edit|Write)`: 수정 파일 ruff / prettier 자동 포맷

## 병렬 작업
기능 1개 = 브랜치 1개. backend/frontend처럼 겹치지 않는 기능은 git worktree로 동시에 진행하고 PR로 합친다.

## 사람 체크포인트
DB 스키마·API 계약 확정, acceptance 변경, 배포·Secret 설정, 금요일 쇼케이스 전 리뷰.

## 발표 포인트
하네스 자체가 스타터킷의 일부 → "Fork한 팀의 AI 에이전트도 같은 품질 기준으로 새 서비스를 만든다".
progress.md 로그 = 트러블슈팅 보고서의 근거.

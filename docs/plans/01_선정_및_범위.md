# 01. 주제 선정 및 스타터킷 범위

## 선정 결과
| 항목 | 내용 |
|---|---|
| 주제 | **챗봇형 AI 서비스 스타터킷** (4개 주제 중 ①) |
| 샘플 서비스 | **AI 배움일기 코치** |
| 한 줄 설명 | 인증·대화 이력·LLM 스트리밍·CI/CD·에이전트 하네스가 갖춰져, Fork 후 바로 대화형 AI 서비스를 시작할 수 있는 보일러플레이트 |

## 선정 근거
- **필수 요구사항과 겹치는 정도가 가장 크다**: JWT·예외 처리·LangChain·CI/CD 위에 스트리밍과 이력만 더하면 되므로, 평가 비중이 큰 CI/CD·Fork 검증·문서화에 시간을 쓸 수 있다
- **시연 체크리스트 "LLM 결과를 실시간 확인"에 스트리밍이 직접 대응**한다
- **산출물 템플릿의 예시가 챗봇형 기준**이라 작성이 수월하다
- 2주 기간에서 RAG(파싱·청킹 품질)나 대시보드(범용화)를 주제로 잡는 것보다 위험이 낮다

## 차별화 포인트
1. **AI-native 스타터킷**: CLAUDE.md·feature_list·verify.sh·서브에이전트·스킬을 포함해 Fork한 사람의 AI 에이전트도 규칙대로 커스터마이징 (→ 03 문서)
2. **pgvector RAG 모듈 on/off**: 별도 벡터 DB 없이 PostgreSQL 하나로 확장
3. **토큰 사용량·비용 로깅**

## 포함 / 제외
| 구분 | 기능 |
|---|---|
| 필수(코어) | 계층형 FastAPI, SQLAlchemy+Alembic, JWT(가입·로그인·리프레시), 공통 예외·로깅, Next.js 인증 화면·공통 컴포넌트·API 클라이언트, LangChain 모듈(프롬프트 템플릿·공급자 교체), 대화 이력, SSE 스트리밍, .env 분리, CI/CD, API 테스트 |
| 선택(포함) | RAG(on/off), 토큰 사용량, Docker Compose, Swagger 정리, (여유 시) 프로젝트 생성 스크립트 |
| 제외 | OAuth 소셜 로그인, 역할 기반 권한(RBAC), 결제, 다국어, 파일 업로드 UI 고도화 |

제외 이유: 2주 범위와 "새 서비스마다 반복되는 공통 작업"이라는 재사용 기준에 맞지 않거나 서비스별로 요구가 크게 달라진다.

## 재사용 기준 (모듈을 스타터킷에 넣을지 판단)
1. 두 개 이상의 다른 AI 서비스에서 **수정 없이** 쓰이는가 → 코어
2. 설정값(.env)이나 프롬프트 교체만으로 바뀌는가 → 코어 + 설정 포인트
3. 특정 도메인 로직인가 → `samples/`로 분리

# 02. 스타터킷 설계서 (초안)

> 최종 제출본은 산출물 템플릿 1번 구조로 이 문서를 완성한다. 그림·흐름은 [../architecture.md](../architecture.md).

## ① 개요
| 항목 | 내용 |
|---|---|
| 주제 | 챗봇형 AI 서비스 스타터킷 (AX Chat Starter) |
| 해결 문제 | 새 AI 서비스마다 반복되는 인증·DB·LLM 연동·스트리밍·CI/CD 셋업 |
| 대상 사용자 | 스타터킷을 Fork해 대화형 AI 서비스를 만드는 개발자 (및 그의 AI 코딩 에이전트) |
| 스택 | FastAPI, SQLAlchemy 2.0, Alembic, PostgreSQL 17 + pgvector, Next.js 16, shadcn, zustand, LangChain |
| LLM | LangChain `init_chat_model` — 강의 제공 API (TBD), 테스트는 fake 공급자 |

## ③ 디렉터리와 모듈
| 모듈 | 역할 | Fork 후 그대로 | Fork 후 수정 |
|---|---|---|---|
| `backend/src/app/core` | 설정·DB·보안·예외·로깅 | 전부 | 설정 키 추가 |
| `backend/src/app/domain/auth` | 가입·로그인·리프레시·내 정보 | 전부 | 사용자 필드 추가 시 |
| `backend/src/app/domain/chat` | 대화·메시지·SSE 스트리밍 | 대부분 | 시스템 프롬프트 연결 |
| `backend/src/app/domain/usage` | 토큰 사용량·비용 | 전부 | 단가표 |
| `backend/src/app/llm` | 공급자 팩토리·프롬프트·체인·RAG | providers, fake | prompts, chains |
| `backend/src/app/domain/<new>` | 서비스 고유 도메인 | — | 새로 작성 (`/add-domain-model`) |
| `frontend/app/(auth)` | 로그인·회원가입 | 전부 | 브랜딩 |
| `frontend/app/(main)/chat` | 채팅 UI | 대부분 | 화면 문구·레이아웃 |
| `frontend/api`, `store` | API 클라이언트·인증 상태 | client, auth | 도메인 API 추가 |
| `.github/workflows` | CI 게이트·배포 | ci.yml | deploy 대상·Secret |
| `harness/`, `.claude/`, `CLAUDE.md` | 에이전트 하네스 | 구조 | feature_list 내용 |

## ⑤ CI/CD
| 단계 | 내용 | 실패 시 |
|---|---|---|
| 빌드 | uv sync --locked, npm ci, next build | 배포 중단 |
| 테스트 | ruff·mypy·import-linter·pytest, eslint·tsc | 배포 중단 |
| 배포 게이트 | main + CI success (`workflow_run`) | 배포 미실행 |
| 배포 | 대상 TBD, 배포 후 `/health` 확인 | 이전 버전 유지 |

## ⑥ 주요 설계 결정
- [ADR-0001 모노레포 + 에이전트 하네스](../decisions/ADR-0001-monorepo-and-harness.md)
- [ADR-0002 기술 스택](../decisions/ADR-0002-stack.md)
- 계층 규칙은 문서가 아니라 import-linter로 **기계적으로 강제**
- 비밀 값은 `.env`(로컬)·GitHub Secrets(CI/배포)로만, `.env.example`이 계약
- LLM 공급자는 `get_chat_model()` 한 곳에서만 생성 → 교체 비용 = .env 수정
- 테스트는 fake LLM → API 키 없이 CI 통과 (Fork 직후에도 녹색)

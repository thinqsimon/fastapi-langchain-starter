# 재사용성 검증 기록

Fork한 새 환경에서 **문서만 보고** 실행되는지 확인한 기록입니다.
`make fork-verify`가 임시 폴더에 저장소를 새로 clone해 `init` → `verify`를 수행합니다.
커밋되지 않은 파일은 포함되지 않으므로, 실제로 Fork한 사람과 같은 조건입니다.

## 2026-10-15 · 1차 (자동 검증)

| 항목 | 내용 |
|---|---|
| 환경 | macOS 27.0.1 (Apple Silicon), Python 3.13, Node 22, Docker Desktop 4.95.0 |
| 명령 | `make fork-verify` |
| 결과 | **통과** — 의존성 설치 → DB 기동 → 마이그레이션 → verify(린트·타입·계층·테스트 69개·빌드) |

### 이 검증으로 찾아낸 문제

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `make init`이 DB 포트 충돌로 실패 | 검증용 DB가 개발용 DB와 같은 5432를 쓰려 함. 이미 PostgreSQL을 쓰는 사람도 같은 문제를 겪는다 | `POSTGRES_PORT`로 포트를 바꿀 수 있게 하고, fork-verify는 55432 사용 |
| 2 | `make init` 후 서버가 뜨지 않고 설정 오류 | `.env.example`의 `LLM_PRICE_INPUT_PER_1M=`(빈 값)이 숫자로 파싱되지 않음. **Fork 직후 100% 재현되는 치명적 문제** | 비워 둔 선택 설정은 '설정하지 않음'으로 처리하고 회귀 테스트 추가 |

> 두 문제 모두 평소 개발 환경에서는 드러나지 않았습니다(이미 `.env`와 DB가 있었기 때문).
> Fork 검증을 자동화한 덕분에 발견했습니다.

### 이 과정에서 찾아낸 문제

| # | 증상 | 원인 | 조치 |

| 3 | 환경 변수 수정 후 서버가 죽음 (`SettingsError`) | `CORS_ORIGINS`를 JSON 배열로만 해석. 대시보드 입력에서 따옴표·대괄호를 빠뜨리기 쉽다 | JSON과 쉼표 구분을 모두 수용하고, 틀렸을 때 고치는 방법을 안내 |

| 5 | uv 버전 경고 | 빌드 도구 버전 범위를 좁게 고정 | 범위 완화 |

## 2026-10-26 · 3차 (다른 사람의 컴퓨터 · Windows)

팀원이 **Windows PC**에서 `service/diary-coach` 브랜치를 받아 로컬 실행까지 진행했습니다
(AI 에이전트의 도움을 받음. 서비스 브랜치 `harness/progress.md` 세션 19).

| 항목 | 내용 |
|---|---|
| 환경 | Windows, Docker Desktop(WSL), Python 3.13, 기본 인코딩 cp949 |
| 결과 | **실행 성공** — DB 기동·마이그레이션·로그인·일기·회고 확인. 배포는 하지 않음 |

### 이 검증으로 찾아낸 문제

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 6 | Alembic이 `UnicodeDecodeError: cp949`로 설정을 못 읽음 | `alembic.ini`의 한글 주석을 Windows 기본 로캘로 읽음 | 주석을 ASCII 영문으로 유지 ([트러블슈팅 9](troubleshooting.md#9-windows-로컬-실행-alembic-인코딩과-예약-포트)) |
| 7 | 포트 8000에서 `WinError 10013` | Docker/WSL 기동 뒤 Windows가 8000 근처를 예약 | 예약 범위 밖 포트(예: 18000) 사용과 확인 명령 안내 |

## 2026-11-02 · 4차 (자동 검증 재실행)

| 항목 | 내용 |
|---|---|
| 환경 | macOS (Apple Silicon), Python 3.13.15, Node 22, Docker Desktop. 개발용 DB 컨테이너 여러 개가 떠 있는 평소 상태 |
| 명령 | `make fork-verify` (main) |
| 결과 | 처음 실행 **실패**(테스트 92개) → 스크립트 결함 수정 후 **통과** — 테스트 165개, 커버리지 97%, 프론트엔드 빌드 |

### 이 검증으로 찾아낸 문제

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 8 | 테스트 92개가 `Can't locate revision identified by '…'`로 실패 | fork-verify가 `DATABASE_URL`만 검증용 포트(55432)로 바꾸고 `TEST_DATABASE_URL`은 그대로 둬, 테스트가 **개발자 PC의 5432 DB**에 붙었다. 그 DB는 다른 브랜치 스키마였다. 5432에 아무것도 없는 새 PC에서는 DB 테스트가 건너뛰어져 **거짓 통과**가 된다 | `scripts/fork-verify.sh`가 `TEST_DATABASE_URL`도 검증용 DB로 지정 |

> 1차 "통과" 기록은 이 결함 때문에 DB 테스트를 건너뛴 결과였을 수 있습니다. 4차부터가 테스트까지 포함한 검증입니다.

## 2026-11-05 · 5차 (실제 Fork 프로젝트 · 처음부터 배포)

작성자가 사이드 프로젝트로 이 스타터킷을 Fork해 **AI ONE PARK**(아파트 우선주차 운영 서비스)를 완성하고 배포했습니다. 문서를 보고 진행했다는 것은 작성자의 설명입니다.

| 항목 | 내용 |
|---|---|
| 저장소 | 별도 저장소(주소는 적지 않음). GitHub의 Fork 표시는 없지만 이 저장소를 `upstream`으로 두고 스타터킷의 커밋 이력을 이어받았고, README에도 Fork라고 적혀 있습니다 |
| 규모 | 커밋 120개, 스타터킷에 없던 주차 판정·관리실 기능 추가 |
| 배포 | Render·Vercel(주소는 적지 않음) |
| 2026-11-05 확인 | 백엔드 `/health` → `{"status":"ok"}`, 프론트엔드 200 |

같은 날 `make fork-verify`도 다시 통과했습니다.

|---|---|

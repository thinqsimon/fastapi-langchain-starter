# 재사용성 검증 기록

Fork한 새 환경에서 **문서만 보고** 실행되는지 확인한 기록입니다.
`make fork-verify`가 임시 폴더에 저장소를 새로 clone해 `init` → `verify`를 수행합니다.
커밋되지 않은 파일은 포함되지 않으므로, 실제로 Fork한 사람과 같은 조건입니다.

## 2026-10-15 · 1차 (자동 검증)

| 항목 | 내용 |
|---|---|
| 환경 | macOS 27.0.1 (Apple Silicon), Python 3.13, Node 22, Docker Desktop 4.95.0 |
| 명령 | `make fork-verify` |
| 결과 | **통과** — 의존성 설치 → DB 기동 → 마이그레이션 → verify(린트·타입·계층·테스트 69개·빌드) |

### 이 검증으로 찾아낸 문제

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | `make init`이 DB 포트 충돌로 실패 | 검증용 DB가 개발용 DB와 같은 5432를 쓰려 함. 이미 PostgreSQL을 쓰는 사람도 같은 문제를 겪는다 | `POSTGRES_PORT`로 포트를 바꿀 수 있게 하고, fork-verify는 55432 사용 |
| 2 | `make init` 후 서버가 뜨지 않고 설정 오류 | `.env.example`의 `LLM_PRICE_INPUT_PER_1M=`(빈 값)이 숫자로 파싱되지 않음. **Fork 직후 100% 재현되는 치명적 문제** | 비워 둔 선택 설정은 '설정하지 않음'으로 처리하고 회귀 테스트 추가 |

> 두 문제 모두 평소 개발 환경에서는 드러나지 않았습니다(이미 `.env`와 DB가 있었기 때문).
> Fork 검증을 자동화한 덕분에 발견했습니다.

## 2026-10-15 · 2차 (실제 배포 환경)

Supabase + Render + Vercel에 배포한 뒤 운영 환경에서 직접 확인했습니다.

| 확인 | 결과 |
|---|---|
| 백엔드 기동 | `https://diary-coach.onrender.com/health` → `{"status":"ok"}` |
| 마이그레이션 | Supabase에 테이블 5개 생성 |
| 회원가입·로그인 | 201 / 토큰 발급 |
| LLM 스트리밍 | 실제 OpenAI 응답 수신 |
| 일기 초안 생성 | 구조화 출력 3항목 정상 |
| CORS | Vercel 출처 허용 확인 |

### 이 과정에서 찾아낸 문제

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 3 | 환경 변수 수정 후 서버가 죽음 (`SettingsError`) | `CORS_ORIGINS`를 JSON 배열로만 해석. 대시보드 입력에서 따옴표·대괄호를 빠뜨리기 쉽다 | JSON과 쉼표 구분을 모두 수용하고, 틀렸을 때 고치는 방법을 안내 |
| 4 | 루트 경로 404와 "No open ports detected" | 배포 플랫폼이 `/`를 확인하는데 라우트가 없었음 | 서비스 정보를 돌려주는 루트 라우트 추가 |
| 5 | uv 버전 경고 | 빌드 도구 버전 범위를 좁게 고정 | 범위 완화 |

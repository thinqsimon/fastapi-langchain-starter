# 트러블슈팅 보고서

프로젝트 기간 동안 실제로 막혔던 문제와 해결 과정을 정리했습니다.
원천 기록은 세션마다 남긴 [harness/progress.md](../../harness/progress.md)입니다.

문제를 **영향 범위**로 나눴습니다. 특히 아래 세 건은 **Fork한 사람이 그대로 겪었을 문제**라
스타터킷 품질에 직결됩니다.

| # | 문제 | 심각도 | 어떻게 발견했나 |
|---|---|---|---|
| 1 | 빈 설정값 때문에 Fork 직후 서버가 뜨지 않음 | 높음 | `make fork-verify` |
| 2 | 내부 오류 메시지(API 키 문구)가 클라이언트에 노출 | 높음 | 브라우저 E2E |
| 3 | 저장 직후 사용자가 쓰던 글이 지워짐 | 중간 | 브라우저 E2E |

---

## 1. Fork 직후 서버가 뜨지 않음 (가장 심각)

**증상**
깨끗하게 clone한 환경에서 `make init` 후 서버가 기동되지 않고 설정 검증 오류가 났습니다.

```
pydantic_core.ValidationError: 2 validation errors for Settings
... float_parsing
```

**원인**
`.env.example`에 선택 설정을 `LLM_PRICE_INPUT_PER_1M=`처럼 **빈 값으로** 적어 두었습니다.
이 필드의 타입은 `float | None`인데, 빈 문자열은 숫자로 변환되지 않아 검증에서 실패했습니다.

평소 개발 환경에서는 전혀 드러나지 않았습니다. 이미 값이 채워진 `.env`를 쓰고 있었기 때문입니다.
**Fork한 사람은 100% 겪는 문제**였습니다.

**해결**
비워 둔 값을 "설정하지 않음"으로 해석하도록 검증기를 추가했습니다.

```python
@field_validator("LLM_BASE_URL", "LLM_PRICE_INPUT_PER_1M", "LLM_PRICE_OUTPUT_PER_1M", mode="before")
@classmethod
def _blank_means_unset(cls, value: object) -> object:
    if isinstance(value, str) and value.strip() == "":
        return None
    return value
```

**재발 방지**
- 회귀 테스트 추가: 선택 설정을 모두 빈 값으로 줘도 설정이 만들어지는지 확인
- 설정과 `.env.example`이 어긋나면 실패하는 테스트 3개 추가
- `make fork-verify`를 정기적으로 실행

**배운 것**
"내 컴퓨터에서는 된다"를 깨는 유일한 방법은 **내 환경을 쓰지 않고 검증하는 것**이었습니다.

## 2. 내부 오류 메시지가 클라이언트에 노출

**증상**
LLM 호출이 실패하자 브라우저로 이런 내용이 그대로 전달됐습니다.

```
event: error
data: Missing credentials. Please pass an `api_key`, ... or set the `OPENAI_API_KEY` ...
```

**원인** (두 가지가 겹침)
1. `get_chat_model()` 호출이 `try` 블록 **밖**에 있어, 모델 초기화 실패가 우리 예외(`LLMError`)로 묶이지 않았습니다.
2. 라우터가 `str(exc)`를 그대로 이벤트에 실어 보냈습니다.

스트리밍은 HTTP 상태 코드를 이미 보낸 뒤라 일반 예외 핸들러가 개입할 수 없는 구간이었습니다.
일반 API 경로는 BE-01에서 내부 메시지를 숨기도록 처리했지만, **스트리밍 경로만 빠져 있었습니다.**

**해결**
- 모델 생성을 `try` 안으로 옮겨 초기화 실패까지 `LLMError`로 묶음
- 라우터에서 `AppError`는 우리가 쓴 메시지만, 그 외는 일반 문구만 전달하고 상세는 로그에만 기록

**재발 방지**
내부 문자열이 응답에 섞이지 않는지 단정하는 회귀 테스트를 추가했습니다.

```python
assert INTERNAL_SECRET not in res.text
assert "api_key" not in res.text
```

**배운 것**
예외 처리 정책은 **모든 응답 경로에 적용했는지** 확인해야 합니다. 스트리밍처럼 일반 흐름을 벗어나는
구간은 따로 점검이 필요했습니다.

## 3. 저장 직후 쓰던 글이 지워짐

**증상**
일기를 저장한 뒤 바로 다음 내용을 입력하면 입력칸이 비워졌습니다. E2E 테스트가 간헐적으로 실패했습니다.

**원인**
저장 성공 후 입력칸을 비우는 처리가 **목록을 다시 읽는 비동기 작업보다 늦게** 도착했습니다.
그 사이 사용자가 입력한 내용이 초기화됐습니다.

**해결**
순서를 바꿔, 목록을 먼저 읽고 나서 입력칸을 비우도록 했습니다.

**재발 방지**
스트리밍 중인 말풍선에 `data-pending` 표시를 넣어, 테스트가 "저장이 끝난 상태"를 정확히 기다릴 수 있게 했습니다.

**배운 것**
처음에는 테스트가 잘못됐다고 생각했지만, 브라우저 상태를 직접 찍어 보니 **실제 사용자도 겪는 문제**였습니다.
테스트 실패를 테스트 탓으로 돌리기 전에 확인해야 했습니다.

---

## 4. 브라우저에서만 응답이 저장되지 않음

**증상**
API 테스트는 통과하는데, 브라우저로 대화하면 AI 응답이 DB에 남지 않았습니다.

**원인**
E2E 스크립트가 `.env`의 실제 OpenAI 설정을 사용했는데 키가 없어 스트림이 오류로 끝났습니다.
API 테스트는 가짜 LLM을 쓰도록 되어 있어 이 문제가 드러나지 않았습니다.
**검증 수단마다 설정이 달랐던 것**이 원인이었습니다.

**해결** E2E도 가짜 공급자를 강제하도록 수정했습니다.

**재발 방지** CI 설정과 E2E 스크립트에 `LLM_PROVIDER=fake`가 들어 있는지 **테스트로 검사**합니다.

## 5. 자동 포맷 도구가 편집 중인 코드를 망가뜨림

**증상**
코드를 여러 번에 나눠 고치는 동안 `func`, `Uuid`, `Path` 같은 import가 사라져 `NameError`가 연달아 났습니다.

**원인**
파일 저장 후 자동으로 돌던 `ruff check --fix`가, **아직 사용되지 않은** import를 미사용으로 보고 삭제했습니다.

**해결** 자동 실행은 포맷만 하도록 바꾸고, 린트는 커밋 전 검증 단계가 맡도록 했습니다.

**배운 것** 자동 수정 도구에는 **되돌릴 수 있는 작업만** 맡겨야 합니다.

## 6. 마이그레이션 파일을 지운 뒤 DB가 꼬임

**증상** `alembic upgrade head`가 `Can't locate revision identified by '...'`로 실패했습니다.

**원인** downgrade가 실패한 상태에서 마이그레이션 파일을 먼저 지웠습니다.
DB의 `alembic_version`은 존재하지 않는 리비전을 가리키게 됐습니다.

**해결** 테이블과 `alembic_version`을 비우고 마이그레이션을 다시 만들었습니다.

**재발 방지** 파일을 지우기 전에 `alembic downgrade base`가 **성공했는지 먼저 확인**합니다.

## 7. 아이폰에서만 보내기 버튼이 화면 밖으로 밀림

**증상** 아이폰 홈 화면 웹앱에서 채팅 입력칸 옆 '보내기' 버튼이 오른쪽에서 잘렸습니다.
크롬으로 돌린 E2E(390px)와 가로 스크롤 검사는 모두 통과한 상태였습니다.

**원인** 실제 아이폰은 글꼴 때문에 입력칸(textarea)의 기본 너비가 더 넓게 계산됩니다(약 305pt).
채팅 영역(flex 항목)에 `min-w-0`이 없어 그 너비 아래로 줄지 못했고, 영역 전체가 화면보다 넓어졌습니다.
바깥이 `overflow-hidden`이라 넘친 부분이 잘려 보일 뿐 가로 스크롤은 생기지 않아, 스크롤 검사에도 걸리지 않았습니다.

**해결** WebKit(iPhone 프로필)에서 입력칸 `cols`를 늘려 같은 현상을 재현(영역 722px)한 뒤, 채팅 영역에 `min-w-0`을 넣었습니다.
같은 조건을 E2E로 고정했고, 고치기 전 코드에서는 실패(버튼 691px)함을 확인했습니다.

**재발 방지** flex 안에서 줄어들어야 하는 영역에는 `min-w-0`을 함께 둡니다(`frontend/CLAUDE.md`).

## 8. 그 밖의 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| `docker` 명령을 찾을 수 없음 | 설치 후 `/usr/local/bin` 링크가 생기지 않음 | PATH에 앱 번들 경로 추가. 가이드 ①에 기록 |
| 타입 검사에서 `LayoutProps`를 못 찾음 | Next 16은 라우트 타입을 `next typegen`으로 생성 | 검사 명령을 `next typegen && tsc --noEmit`으로 변경 |
| 접근 로그가 요청당 두 줄 | uvicorn 로그와 우리 미들웨어 로그가 중복 | uvicorn 쪽 접근 로그를 끔 |
| 포트 충돌 | 수업 예제 서버가 8000, 이전 E2E 서버가 8010에 잔존 | E2E 전용 포트 사용 + 종료 시 포트 기준으로 정리 |
| E2E 선택자 충돌 | Next.js의 route announcer도 `role="alert"` | 화면 요소로 범위를 좁힘. 규칙을 `frontend/CLAUDE.md`에 기록 |
| 테스트가 로컬 `.env`에 좌우됨 | 개발자 설정이 테스트 결과를 바꿈 | 테스트에서 필요한 값을 고정 |
| 서랍을 연 채 화면이 넓어지면 화면이 눌리지 않음 | 서랍 내용만 숨고 반투명 배경은 남음 | 넓어지면 서랍을 닫고, 넓은 화면에서는 열지 않음(test-verifier가 발견) |
| 터치 태블릿에서 삭제 버튼이 안 보이고 글자가 작음 | "터치 기기"를 화면 폭(768px)으로 판단 | `hover`·`pointer` 미디어로 판단 |
| 아이폰에서 입력칸을 누르면 화면이 확대됨 | 입력칸 글자가 16px 미만 | 터치 기기에서는 16px |
| 일기를 교육 플랫폼에 붙여 넣으면 항목 제목과 소제목이 구분되지 않음 | 편집기가 CSS를 버리고 태그만 받아 h2·h3를 비슷하게 크게 그림 | 붙여 넣기용 HTML을 따로 만들어 항목 제목 단계 통일·소제목 '▶ 굵은 글씨'·빈 줄로 구분 |
| 복사 직후 클립보드를 읽는 E2E가 간헐 실패 | 비동기 쓰기가 끝나기 전에 읽음 | '복사됨' 표시를 기다린 뒤 읽음 |
| 로고 추가 후 E2E 12개 실패 | 로고 링크 이름 '배움일기 코치 홈'이 '일기' 부분 일치에 걸림 | 짧은 이름은 `exact: true`로 찾음 |

## 9. Windows 로컬 실행: Alembic 인코딩과 예약 포트

**증상** Alembic이 `UnicodeDecodeError: cp949`로 설정을 읽지 못했습니다.
Alembic의 INI 로더가 기본 로캘 인코딩을 명시해서 UTF-8 한글 주석을 읽다 실패한 것입니다.

**해결** `backend/alembic.ini`의 주석을 ASCII 영문으로 유지합니다. 활성 설정 값은 바꾸지 않습니다.
Windows 기본 인코딩에서 `alembic current`와 `alembic check`로 검증했습니다.

**포트** Docker/WSL 시작 뒤 Windows의 예약 범위에 8000·8010이 포함되면 사용 중인 프로세스가
없어도 `WinError 10013`이 납니다. `netsh interface ipv4 show excludedportrange protocol=tcp`로
확인하고 예약 범위 밖의 포트를 사용합니다. 예: 백엔드 `--host 127.0.0.1 --port 18000`,
프론트엔드 `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:18000`.
프론트엔드 포트가 3000이면 CORS에는 화면 주소 `http://localhost:3000`을 허용합니다.

**마이그레이션 테스트 격리** downgrade/upgrade 왕복 검증은 매번 생성하는
`diary_migration_test_<UUID>` 전용 DB에서만 실행합니다. 공유 DB의 회고·복습 테이블은
되돌리지 않습니다. 이 검증은 DB 생성 권한이 있는 프로젝트의 로컬/CI PostgreSQL 역할을 사용합니다.

## 정리: 무엇이 문제를 찾아냈나

| 검증 수단 | 찾아낸 문제 |
|---|---|
| **`make fork-verify`** | 1번(Fork 직후 기동 실패), DB 포트 충돌 |
| **브라우저 E2E** | 2번(정보 노출), 3번(입력 지워짐), 4번(저장 누락) |
| **커밋 전 검증(`verify.sh`)** | 포맷·타입·계층 규칙 위반을 매번 차단 |
| 단위·API 테스트 | 회귀 방지. 다만 위 1~4번은 **잡지 못했음** |
| **실기기 스크린샷 + WebKit 재현** | 7번(아이폰에서만 버튼이 밀림) — 크롬 E2E로는 드러나지 않았음 |
| **인수조건 검증 에이전트(test-verifier)** | 서랍 배경이 남아 화면이 막히는 문제, 터치 태블릿 판단 오류, 이메일 변경 경합 500 |

가장 큰 교훈은 **검증 수단마다 잡는 문제가 다르다**는 것이었습니다.
단위 테스트만으로는 "내 환경에서만 되는" 문제도, "실제 브라우저에서만 생기는" 문제도 보이지 않았습니다.
